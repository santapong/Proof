## Skill map: 12 → 18

### New skills (six)

| New skill | Role | Scope boundary |
|---|---|---|
| `loop-pattern` | code pattern + framework usage | Applies patterns/idioms/refactorings. GoF, Fowler *Refactoring* 2e, SOLID, language style guides, idiomatic framework use. Distinct from `loop-review`, which only *judges*. |
| `loop-integrate` | platform integration | Third-party/cloud/SaaS integration: OAuth2/OIDC (RFC 6749/9700), webhooks, idempotency keys, rate limits, retry/backoff, contract tests, sandbox→prod promotion, secret handling. |
| `loop-algo` | mechanism and algorithm | Complexity analysis, data-structure selection, invariants and correctness arguments, concurrency mechanisms, benchmark-driven validation. |
| `loop-ship` | deployment strategy and solution | Pre-/at-deploy: blue-green, canary, rolling, feature flags, expand-contract migrations, rollback plans, DORA metrics, release checklist. |
| `loop-incident` | incident analysis and reproduce | Exception state: severity triage, comms, mitigate-before-diagnose, reproduction harness, timeline, blameless postmortem / correction-of-error. Delegates root cause to `loop-debug`. |
| `loop-operate` | full automation software serve | Steady state: SLI/SLO/error budgets, health watching, self-healing runbooks, SLO-gated auto-rollback, alert design, on-call triage. Carries the autonomy dial wired to `loop-autopilot`'s ladder. |

### The handoff chain (new README narrative)

```
loop-operate  detects  →  loop-incident  mitigates + reproduces
              →  loop-debug  root-causes  →  loop-test  regression
              →  loop-ship  redeploys
```

This chain is what keeps the four adjacent skills from overlapping. `boundary-audit`
(Phase 1) is the node that has to prove the boundaries hold.

### Already covered — no change

`loop-orchestrate` (planning) · `loop-design` (system design) · `loop-review` +
`loop-audit` (risk & security) · `loop-test` (tester) · `loop-autopilot` (autonomous + HITL)

## Execution modes

Lives in the engine, not in a new skill:

- **new** `loop-engine/references/execution-modes.md` — the mode contract
- **amend** `loop-engine/references/harness-policy.md` H8 → point at the mode file
- **amend** `loop-engine/SKILL.md` + `loop-orchestrate/SKILL.md` step 1 → parse `--mode`, `--planner`
- **rewrite** `loop-orchestrate/references/model-routing.md` → Opus 5 fleet + per-mode column

All 18 domain skills inherit the flag because they author scripts through the same
templates. No per-skill mode logic.

| Node kind | `--mode optimize` (default) | `--mode full` |
|---|---|---|
| scout / doc / mechanical | Haiku 4.5, `low` | Opus 5, `high` |
| implement | Sonnet 5, `medium`–`high` | Opus 5, `high` |
| analyze / synthesize | inherit Opus 5, `high` | Opus 5, `xhigh` |
| verify / judge / critic | inherit Opus 5, `high`–`xhigh` | Opus 5, `xhigh` |
| correctness-critical / gating | Opus 5, `max` | Opus 5, `max` |
| planner (the decompose node) | Opus 5, `xhigh` | Opus 5, `max` (`--planner fable` → Fable 5) |
| modifier A (wide fan-out pushes tier down) | active | **disabled** |
| modifier B (error cost pushes tier up) | active | active (already at ceiling) |
| verifier width | 1, or 3 for "thorough" | 3–5 diverse lenses always |
| loop-until-dry threshold | 2 | 3 |
| pre-flight | none | estimate + one confirmation |

**Opus 5 rebaseline.** v0.4.0 predates Opus 5 — `model-routing.md` still declares
"the default fleet caps at Opus 4.8" and hardcodes `claude-opus-4-8` in the table,
the worked example, and `project-plan.workflow.js`. Retiring that is a breaking
documentation change and part of what makes this a 1.0.0.

## Open risks

1. **18 skills strains skill selection.** More skills means more chance Claude picks
   the wrong one. Mitigation: `boundary-audit` writes mutually-exclusive `description:`
   fields with explicit "use X instead when…" pointers.
2. **`loop-operate` needs real infrastructure to be more than prose.** Without a live
   service to observe, its templates are scaffolds, not proven recipes — the same
   honest framing v0.3.0 used for the SCALE rung.
3. **1.0.0 signals API stability.** After this, skill renames become breaking changes.
   The `loop-*` namespace just landed in v0.4.0, so the timing is right.
